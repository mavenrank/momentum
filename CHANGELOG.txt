# Changelog

All notable changes to Momentum will be documented in this file.

The format follows Keep a Changelog conventions, and this project uses Semantic Versioning.

## [0.7.0] - 2026-08-25

### Added
- Added one typed application-command layer for tasks, journal entries, weekly
  notes, areas, habits, maintenance, and atomic command batches. Browser, Tauri,
  CLI, tests, and future automation now share the same domain rules.
- Added explicit scheduling conflict policies: interactive UI operations may
  warn, while CLI and LLM operations reject overlaps unless the caller opts in.
  Clock intervals use half-open boundaries so adjacent blocks remain valid.
- Added a full-store validator covering IDs and counters, dates, clock ranges,
  area and habit references, duplicate records, dangling journal references,
  and active time conflicts.
- Added `scripts/momentum.ts`, a machine-readable CLI with task, journal, week,
  area, habit, batch, inspect, audit, validation, import, and export commands.
- Added atomic CLI writes, cross-process locking, stale-lock recovery,
  optimistic revisions, idempotency keys, dry runs, actor attribution, and an
  audit trail suitable for guarded LLM control.
- Added a dependency-free Python application framework with deterministic
  state-machine, concurrent-writer, conflict, revision, idempotency, and
  year-scale scenarios, plus a reusable web/Tauri import generator.
- Added a seeded load dataset spanning 2,400 tasks, 365 journal entries, 53
  weekly notes, 13 areas, eight habits, and hundreds of habit logs.

### Changed
- Routed planner, calendar, journal, habit, settings, stale-collection, and
  import mutations through the shared command executor instead of exposing raw
  state setters to feature components.
- Replaced quadratic whole-store overlap validation with a per-day interval
  sweep. The same 1,200-task browser import measured about 24 ms after the
  change, down from roughly ten minutes during the initial load test.
- Accepted the Tauri experiment as a supported second distribution target and
  carried the same command, validation, CLI, and test behavior into the shell.
- Added `bun run check:full` to run TypeScript, lint, Bun unit tests, and Python
  application/load tests together.

### Fixed
- Fixed journal `@T-...` references truncating device suffixes, which prevented
  references to newly created device-tagged tasks from resolving.
- Fixed numeric dates appearing before time ranges from causing the parser to
  consume only the first clock value and leave the range tail in the title.
- Fixed task-ID parsing capture groups so concurrent CLI writers retain valid,
  monotonically advancing counters and unique IDs.
- Fixed the standalone year generator so both direct-script and Python module
  invocation work consistently on Windows.

## [0.6.0] - 2026-08-04

### Added
- Added a Tauri 2 desktop shell that embeds the existing React/Vite interface
  in the operating-system WebView and produces a compact Windows NSIS package.
- Added a native filesystem repository using plain, deterministic JSON split by
  task creation month, plus files for areas, habits, habit logs, weekly notes,
  metadata, and installation-specific settings.
- Added a native Data view card that shows the active data directory and lets
  the user adopt or seed another folder through the system folder picker.
- Added automated round-trip, deterministic serialisation, diff-only write,
  deletion, and task-counter recovery tests for the Tauri store.
- Added a repeatable Windows measurement script and a detailed evaluation of
  installer size, startup behavior, memory cost, durability, and recovery.

### Changed
- The shared repository boundary now selects IndexedDB in browsers and the
  filesystem backend inside Tauri without changing planner components.
- Tauri writes changed files through temporary siblings and atomic renames, and
  leaves unchanged month files untouched to keep sync and git diffs quiet.
- Vite now pins the native development URL to port 5173 and ignores Rust build
  output so the shell cannot silently attach to the wrong development server.

### Security
- Filesystem capabilities are limited to app data by default; a small Rust
  command expands access only to a directory explicitly selected by the user.

## [0.5.0] - 2026-08-04

### Added
- Added time-blocking: a toggle swaps either planner lens for an hour grid over
  the same days, with tasks drawn where they fall, drag to place and drag either
  edge to resize. Overlapping blocks share the lane side by side. The mode is
  shared between Today and Week, with a Settings option to keep them separate.
- Added a right-click action menu on task cards covering details, completion,
  priority, area, scheduling, follow-ups and deletion.
- Added a hover row on task cards: a follow-up button, and a two-step "pull to
  Pool" that clears the date and time together.
- Added editable field chips to Quick Add, so anything the parser detects can be
  overridden before the task is created.
- Added persistent storage requests and folder-backed JSON snapshots, keeping
  the most recent thirty. Browsers without a local-disk picker download the
  snapshot instead.
- Added `scripts/momentum-data.mjs`, which splits an export into a separate
  private git repository of JSON and reassembles it into an importable bundle.
- Added briefs in `docs/prompts/` for provisioning the data repository and for a
  Tauri shell experiment.

### Changed
- Tasks are stored as individual records rather than nested inside the day that
  created them, and saves now write only what changed instead of clearing every
  table and rewriting it. Deletions leave tombstones, changed records are
  stamped with `updatedAt`, and new task IDs carry a per-installation tag.
- Merged the week view's Unscheduled and Pool panels into one filtered inbox.
- Both planner lenses now share one header, so the controls they have in common
  stay in place when switching between them.
- Raised the interface to a 110% baseline and lifted every sub-11px type size.
- Storage failures are reported beside the theme toggle rather than as a banner
  above the workspace, and now include the browser's own error message.

### Fixed
- Fixed the week strip growing and shrinking as tasks gained detail; columns now
  divide the available height evenly and scroll independently.
- Fixed the Quick Add preview shifting the board as the parse changed.
- Fixed the follow-up prompt interrupting every single task completion.

## [0.4.0] - 2026-08-03

### Added
- Added Quick Add: one input parses natural language into structured tasks, with
  inline token highlighting and a live preview of the parsed fields.
- Added area autocomplete on `#`, with Tab completion and on-the-fly creation.
- Added a Settings section for managing areas: add, rename, recolour, archive,
  and restore the defaults.
- Added a Calendar section with a continuously scrolling month grid, viewport-
  sized rows, month-boundary snapping, and a floating month/year heading.
- Added stable task IDs (`T-YYYYMMDD-NNNN`) and a task relationship graph.
- Added an optional one-line `summary` and an optional long-form `description`
  per task, edited in a task detail dialog.
- Added a visible completion checkbox on every task card.
- Added follow-up prompting on completion, with presets.
- Added `@`-mention task references in the Journal, tracked in `taskReferences`.
- Added a Logseq markdown export, one page per task.
- Added dark mode with a theme toggle.
- Added drag-and-drop day assignment in the Week view, plus `Ctrl+Shift+1`–`7`.
- Added automatic collection of tasks left unfinished from the day before
  yesterday or earlier back into the Pool.
- Added a parser test suite (`bun test`) and a combined `bun run check`.

### Changed
- Moved persistence from localStorage to IndexedDB via Dexie, with debounced
  writes, cross-tab sync, and quota-error surfacing. localStorage now holds only
  the theme preference.
- Migrated the data model to v2: statuses are Pool/Planned/Scheduled/Doing/
  Waiting/Done and priorities are Must/Should/Could/Want. v1 data migrates on
  first launch and on import.
- Replaced plain CSS with Tailwind CSS v4 and source-owned shadcn/ui components.
- Replaced the persistent sidebar with a compact top navigation bar.
- Rebuilt the Today view as a three-day board that looks back only while
  yesterday still has unfinished work, with the Pool as an adjacent rail.
- Rebuilt the Week view around unscheduled and pool panels above a seven-day strip.

### Removed
- Removed the task composer, per-task status dropdowns, and status sections.
- Removed the `topFocus` field and task categories.
- Removed completion percentages and counts from the calendar.

## [0.3.0] - 2026-06-06

### Changed

## [0.2.0] - 2026-06-04

- Added categorized daily tasks for top priority, to-do, low priority, and follow-up.

### Changed
